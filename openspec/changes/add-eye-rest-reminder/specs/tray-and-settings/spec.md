## 目的

通过系统托盘和本地设置页面，让用户无需打开主窗口即可查看提醒状态、控制提醒并保存个人偏好。

## ADDED Requirements

### Requirement: 系统托盘控制

系统必须在 Windows 系统托盘中运行，并提供打开应用、查看当前提醒状态、开始休息、暂停提醒和退出应用等操作。

#### Scenario: 用户通过托盘暂停提醒

- **当** 用户从系统托盘选择一个支持的暂停操作
- **那么** 系统必须暂停指定时长的提醒，并更新托盘中显示的状态

### Requirement: 本地设置持久化

系统必须将用户设置保存在 Windows 本地设备中，并在下次启动时恢复。核心提醒功能不得要求用户登录、联网或使用云服务。

#### Scenario: 用户修改设置后重启应用

- **当** 用户修改设置并重启应用
- **那么** 系统必须在启动时加载已保存的设置

### Requirement: 护眼时间表设置

设置页面必须展示并允许保存用眼间隔、休息时长、延后提醒时长和提前提醒时间，以及各项的有效范围和校验反馈。提前提醒默认值必须为 30 秒，支持范围必须为 0 至 300 秒，其中 0 表示不提前显示提醒。设置页面还必须允许选择“黑屏遮罩 + 休息倒计时”或“直接锁定 Windows”，默认选择黑屏遮罩，并明确说明锁定模式需要用户自行解锁。

#### Scenario: 用户查看时间表设置

- **当** 用户打开提醒设置页面
- **那么** 系统必须显示用眼间隔、休息时长、延后提醒时长、提前提醒时间和当前休息方式
- **并且** 系统必须说明提醒会以透明桌面动画固定呈现；当用户未处理提前提醒直至用眼截止时会自动开始休息，开始休息后会按选择显示覆盖所有屏幕的黑屏遮罩，或直接锁定 Windows

#### Scenario: 用户保存有效时间表

- **当** 用户保存处于支持范围内的用眼间隔、休息时长、延后提醒时长和提前提醒时间
- **那么** 系统必须持久化这些值
- **并且** 下次启动应用后必须恢复这些值

### Requirement: Windows 安装包交付与兼容性

第一版系统必须交付可直接运行的 Windows x64 `.exe` 安装程序。该安装程序必须支持在 Windows 10 x64 和 Windows 11 x64 上安装和启动应用，且用户安装后不得需要自行安装 Node.js、npm 或 Electron。第一版不得承诺支持 Windows 32 位、Windows 7、Windows 8、Windows 8.1 或 Windows ARM64。

#### Scenario: 用户在受支持系统上安装

- **当** 用户在 Windows 10 x64 或 Windows 11 x64 上运行安装程序
- **那么** 安装程序必须能够完成安装并提供启动 keep-eyes 的入口

#### Scenario: 用户启动已安装应用

- **当** 用户完成安装后从开始菜单或安装完成页面启动 keep-eyes
- **那么** 应用必须能够启动并进入正常的主窗口或系统托盘运行状态

### Requirement: 选择安装路径

Windows 安装程序必须在安装过程中提供安装路径选择界面，并显示一个可写入的默认安装路径。用户必须能够在安装前选择另一个有效且可写入的本地路径；安装程序必须在开始复制应用文件前校验所选路径是否可用。

#### Scenario: 用户使用默认安装路径

- **当** 用户未修改安装程序提供的默认安装路径
- **那么** 安装程序必须将 keep-eyes 安装到该默认路径

#### Scenario: 用户选择自定义安装路径

- **当** 用户选择一个有效且可写入的自定义本地路径并继续安装
- **那么** 安装程序必须将 keep-eyes 安装到该自定义路径

#### Scenario: 用户选择无效安装路径

- **当** 用户选择不存在、不可写入或不允许安装的路径
- **那么** 安装程序必须显示明确错误并阻止继续安装，直到用户选择有效路径

### Requirement: Windows 标准卸载

安装完成后，系统必须在 Windows 已安装应用列表中提供 keep-eyes 的卸载入口，并在安装目录中提供可执行的卸载程序。开始卸载时，卸载程序必须停止正在运行的 keep-eyes 后台或系统托盘进程，并删除应用程序文件、开始菜单入口、快捷方式和卸载注册信息。

#### Scenario: 用户从 Windows 设置卸载

- **当** 用户在 Windows 的已安装应用列表中选择卸载 keep-eyes 并确认
- **那么** 系统必须启动 keep-eyes 卸载程序并完成标准卸载流程

#### Scenario: 卸载时应用正在运行

- **当** 用户开始卸载且 keep-eyes 正在运行
- **那么** 卸载程序必须先请求应用正常退出，或提示用户关闭应用后再继续

### Requirement: 卸载时保留或删除本地数据

普通卸载必须默认保留用户设置和本地提醒状态。卸载程序必须提供明确且默认不选中的“删除全部设置和本地数据”选项；只有用户明确选择该选项时，才可以删除应用数据目录。

#### Scenario: 用户执行普通卸载

- **当** 用户执行卸载且未选择删除设置和本地数据
- **那么** 卸载程序必须删除应用程序文件但保留用户设置和本地提醒状态

#### Scenario: 用户选择彻底删除数据

- **当** 用户执行卸载并明确选择删除全部设置和本地数据
- **那么** 卸载程序必须删除应用程序文件、用户设置和本地提醒状态

#### Scenario: 用户重新安装并保留过数据

- **当** 用户曾使用默认卸载选项卸载 keep-eyes 后重新安装应用
- **那么** 应用必须能够恢复之前保留的用户设置和本地提醒状态

## MODIFIED Requirements

### Requirement: 系统托盘必须显示可识别图标

Windows 系统托盘中的 keep-eyes 项必须显示由应用提供的可识别且非空白图标，使用户能够辨认对应软件。图标资源必须能够在本地开发运行和安装后的应用中稳定加载，不得依赖不确定的当前工作目录。系统在创建托盘前必须检查图像是否为空；图像创建失败时必须明确报错，不得静默创建空白托盘项。

#### Scenario: 应用创建系统托盘

- **当** keep-eyes 启动并创建系统托盘
- **那么** 托盘项必须显示可识别的 keep-eyes 图标
- **并且** 图标不得为空白或完全透明

#### Scenario: 托盘图像创建失败

- **当** 应用无法从内置资源创建有效托盘图像
- **那么** 系统必须明确报告图标创建失败
- **并且** 不得将空图像静默传给托盘组件
