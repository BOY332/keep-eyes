## 目的

提供唯一且醒目但不妨碍正常工作的专注提醒体验：用眼计时到期前以所有已连接显示器顶部的透明置顶紧凑面板提示用户处理提醒；用户主动开始休息后按选择显示黑屏遮罩或锁定 Windows，同时保持由应用控制的休息倒计时。

## ADDED Requirements

### Requirement: 唯一的专注提醒流程

第一版系统必须且只能使用专注提醒流程，不得向用户提供温和通知或提醒模式选择；休息呈现方式必须支持黑屏遮罩和锁定 Windows 两种选项。用眼计时的剩余时间达到提前提醒时间时，系统必须在仍处于用眼计时状态时显示透明、置顶且非阻塞的紧凑提醒面板；提前提醒出现后，用户未处理直到用眼截止时，系统必须自动开始休息。延后提醒到期时，系统必须显示相同的紧凑提醒并自动开始休息。

#### Scenario: 用户首次使用应用

- **当** 用户首次启动应用且尚未保存设置
- **那么** 系统必须使用唯一的专注提醒流程
- **并且** 设置页面不得显示提醒模式选择

#### Scenario: 提前提醒到期

- **当** 用眼计时剩余时间达到配置的提前提醒时间
- **那么** 系统必须显示透明、置顶且非阻塞的紧凑提醒面板
- **并且** 系统必须保持用眼计时状态
- **并且** 不得显示 Windows 通知、进入休息前请求锁定 Windows，或在用户开始休息前显示黑屏遮罩

#### Scenario: 用户未处理直至用眼截止

- **当** 提前提醒已经显示且用户未作任何操作
- **并且** 用眼截止时间到达
- **那么** 系统必须自动开始休息
- **并且** 必须关闭当前提醒面板，并按所选休息方式进入黑屏遮罩或锁定 Windows

### Requirement: 透明置顶紧凑提醒

提前提醒必须在每个已连接显示器的工作区顶部，分别显示透明、无边框、置顶且醒目的紧凑操作面板。面板不得抢夺焦点，不得覆盖整个显示器工作区，也不得阻止用户继续操作底层应用。面板可以使用平缓的呼吸、渐变或等效低刺激动效，但不得包含快速闪烁、高频颜色切换或伪装成 Windows 系统界面的内容。面板必须显示基于本轮绝对用眼截止时间实时计算的“距离休息还有”倒计时，并提供开始休息、延后提醒、暂停提醒、“知道了”和“我很强，这次先不休息”操作。

#### Scenario: 显示透明紧凑提醒

- **当** 系统进入提前提醒展示阶段或延后提醒到期
- **那么** 系统必须在每个已连接显示器的工作区顶部分别显示由透明原生窗口承载且置顶的紧凑提醒面板
- **并且** 面板必须具有清晰可辨识的半透明底色、描边或阴影轮廓，不得因透明而难以察觉
- **并且** 必须显示持续更新的“距离休息还有”倒计时，以及可操作的开始休息、延后、暂停、“知道了”和“我很强，这次先不休息”按钮
- **并且** 每个显示器最多只能存在一个本轮提醒面板
- **并且** 所有面板必须共享相同的提醒状态、绝对用眼截止时间和倒计时
- **并且** 不得创建覆盖整个显示器工作区的视觉窗口

#### Scenario: 提醒不阻止桌面输入

- **当** 透明紧凑提醒正在显示
- **那么** 窗口不得主动获取焦点
- **并且** 用户必须仍能操作面板之外的底层应用

#### Scenario: 重复提醒事件发生

- **当** 系统已经在一个或多个显示器上显示等待处理的紧凑提醒且再次收到相同状态更新
- **那么** 系统不得在同一显示器创建第二个提醒面板
- **并且** 已有各显示器面板必须复用并保持同步

#### Scenario: 透明提醒创建失败

- **当** 系统无法创建透明紧凑提醒面板
- **那么** 系统必须明确处理该错误或降级为普通置顶专注提醒窗口
- **并且** 不得丢失本次待处理提醒或可操作入口

### Requirement: 多显示器提醒同步

当系统连接多个显示器时，提前提醒必须覆盖所有已连接显示器。每个显示器最多显示一个本轮提醒面板；所有面板必须由同一个提醒状态机和绝对截止时间驱动。用户在任意一个面板上的操作都必须同步作用于本轮所有面板，且同一个操作不得重复触发状态机事件、黑屏遮罩创建或 Windows 锁定请求。显示器连接、断开、重新排列、分辨率或缩放比例变化后，系统必须重新枚举显示器并同步提醒面板集合，不得丢失当前提醒状态或创建重复面板。

#### Scenario: 多显示器显示提醒

- **当** 系统连接多个显示器并进入提前提醒展示阶段
- **那么** 每个已连接显示器都必须显示一个提醒面板
- **并且** 每个面板必须位于对应显示器工作区顶部
- **并且** 所有面板必须显示相同的提醒状态和剩余时间
- **并且** 不得只在单个显示器显示

#### Scenario: 任意显示器操作同步到所有面板

- **当** 用户在任意一个显示器上的提醒面板点击“知道了”、开始休息、延后、暂停或跳过本次休息
- **那么** 状态机必须只处理一次该操作
- **并且** 所有显示器上的同轮提醒面板必须同步执行对应的显示、更新或隐藏行为
- **并且** 开始休息时最多只能执行一次所选休息方式

#### Scenario: 显示器布局发生变化

- **当** 提醒显示期间显示器被连接、断开、重新排列，或分辨率、缩放比例发生变化
- **那么** 系统必须根据当前显示器列表同步提醒面板集合
- **并且** 不得丢失当前提醒状态或创建重复面板
### Requirement: 休息呈现方式

系统必须支持两种可配置的休息呈现方式：覆盖所有已连接显示器的黑屏遮罩并显示休息倒计时，或直接锁定 Windows。默认方式必须为黑屏遮罩。黑屏遮罩模式下，每个显示器必须显示同一休息状态和剩余时间，并提供“提前结束休息”按钮；任意一个按钮操作都必须关闭所有遮罩并开始下一轮用眼计时。锁定 Windows 模式下，系统必须只调用一次 Windows 工作站锁定能力，不得模拟键盘快捷键或调用睡眠、休眠、显示器电源关闭能力。锁定模式下应用无法提供锁屏界面按钮，用户必须自行解锁。

#### Scenario: 黑屏遮罩覆盖所有显示器

- **当** 用户选择黑屏遮罩模式并开始休息
- **那么** 每个已连接显示器都必须显示全屏黑屏遮罩和休息倒计时
- **并且** 所有遮罩必须共享同一绝对休息截止时间

#### Scenario: 提前结束黑屏遮罩休息

- **当** 用户在任意显示器点击“提前结束休息”
- **那么** 系统必须关闭所有显示器上的黑屏遮罩
- **并且** 必须开始下一轮完整的用眼计时

#### Scenario: 直接锁定 Windows

- **当** 用户选择锁定 Windows 模式并开始休息
- **那么** 系统必须调用一次 Windows 工作站锁定能力
- **并且** 不得调用睡眠、休眠或显示器电源关闭能力
- **并且** 不得尝试自动解锁 Windows

#### Scenario: 锁定后解锁

- **当** 用户从 Windows 锁屏界面解锁且休息截止时间尚未到达
- **那么** 系统必须继续本轮休息倒计时
- **并且** 不得把解锁本身视为休息完成

- **当** 用户从 Windows 锁屏界面解锁且休息截止时间已经到达
- **那么** 系统必须开始下一轮完整的用眼计时

### Requirement: 屏幕状态不完成休息

系统不得把显示器亮起、非通过“提前结束休息”发生的遮罩窗口关闭或 Windows 解锁本身视为完成休息。休息只能在休息倒计时结束，或黑屏遮罩模式下用户明确选择“提前结束休息”时完成。

## MODIFIED Requirements

### Requirement: 提前提醒倒计时必须实时更新

提前提醒面板必须显示距离本轮用眼截止的剩余时间。该倒计时必须使用状态机提供的绝对用眼截止时间减去当前时间计算，并至少每秒更新一次；不得因为进入等待处理状态而固定显示 0 秒。窗口重新显示、渲染暂停或系统睡眠恢复后，系统必须立即按当前时间重新计算。

#### Scenario: 提前提醒显示动态剩余时间

- **当** 提前提醒在原定用眼截止之前显示
- **那么** 面板必须显示大于 0 的实际剩余时间
- **并且** 可见数值必须至少每秒更新一次
- **并且** 不得在截止时间尚未到达时持续显示 0 秒

#### Scenario: 提醒窗口恢复后重新校准

- **当** 提醒窗口重新显示、渲染进程经历暂停或系统从睡眠恢复
- **那么** 系统必须根据当前时间和本轮绝对用眼截止时间重新计算剩余时间
- **并且** 不得通过对旧显示值累计减秒来恢复倒计时

### Requirement: “知道了”保持原关闭语义

提前提醒窗口必须提供明确的“知道了”按钮，替代原“关闭”显示文案。用户点击该按钮时，系统必须关闭当前提前提醒窗口及其操作面板，但不得将操作解释为开始休息、延后或暂停；用眼计时和原定截止时间必须保持不变。

#### Scenario: 用户确认知道了

- **当** 提前提醒正在显示且用户点击“知道了”
- **那么** 系统必须关闭当前提醒窗口
- **并且** 必须继续按照原定用眼截止时间计时
- **并且** 不得开始休息、暂停计时或修改下一次提醒时间

#### Scenario: 知道了之后到达原定截止时间

- **当** 用户已经点击“知道了”且原定用眼截止时间到达
- **那么** 系统必须按照既有规则进入休息流程

### Requirement: 用户可以跳过本次休息

提前提醒窗口必须提供“我很强，这次先不休息”按钮。用户点击后，系统必须关闭当前提醒，取消即将发生的本次休息，不进入任何休息呈现方式，也不锁定 Windows，并从点击时刻开始一轮完整的用眼计时。该操作不得被解释为延后、暂停或开始休息。

#### Scenario: 用户跳过本次休息

- **当** 提前提醒正在显示且用户点击“我很强，这次先不休息”
- **那么** 系统必须关闭当前提醒窗口
- **并且** 不得进入休息计时、显示黑屏遮罩或请求锁定 Windows
- **并且** 必须从点击时刻开始一轮完整的用眼计时

#### Scenario: 跳过后旧截止时间到达

- **当** 用户已跳过本次休息且被跳过周期的原定截止时间随后到达
- **那么** 系统不得再次触发被跳过的休息或重新显示对应提醒
- **并且** 必须继续执行新一轮用眼计时

### Requirement: 提前提醒不得妨碍正常工作

提前提醒必须是最上层、透明、非阻塞的紧凑窗口：可以保持在其他窗口之上，但不得抢夺焦点、拦截视觉区域之外的鼠标或键盘输入、锁定 Windows、调用显示器电源关闭能力或阻止用户继续工作。提醒窗口不得覆盖整个桌面工作区；只有操作面板和按钮控件可以接收交互。

#### Scenario: 提前提醒以紧凑面板显示

- **当** 系统进入提前提醒展示阶段
- **那么** 系统必须在每个已连接显示器的工作区顶部显示一个紧凑提醒面板
- **并且** 每个显示器最多只能存在一个本轮提醒面板
- **并且** 所有面板必须共享相同的提醒状态、绝对用眼截止时间和倒计时
- **并且** 不得创建覆盖整个显示器工作区的视觉窗口
- **并且** 面板必须显示实时剩余时间，以及开始休息、延后、暂停、“知道了”和“我很强，这次先不休息”操作

#### Scenario: 用户继续正常工作

- **当** 提前提醒正在显示
- **那么** 用户必须仍能操作底层应用
- **并且** 提醒不得主动改变焦点或阻止底层窗口接收输入

#### Scenario: 用户确认非阻塞提醒

- **当** 用户点击操作面板中的“知道了”
- **那么** 系统必须仅关闭提前提醒，不改变用眼计时计划
