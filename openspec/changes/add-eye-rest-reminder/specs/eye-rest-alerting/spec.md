## 目的

提供唯一且醒目但不妨碍正常工作的专注提醒体验：用眼计时到期前以活动显示器顶部的透明置顶紧凑面板提示用户处理提醒；用户主动开始休息后关闭显示器，同时保持由应用控制的休息倒计时。

## ADDED Requirements

### Requirement: 唯一的专注提醒流程

第一版系统必须且只能使用专注提醒流程，不得向用户提供温和通知、提醒模式选择、关闭显示器模式选择或锁定 Windows 模式。用眼计时的剩余时间达到提前提醒时间时，系统必须在仍处于用眼计时状态时显示透明、置顶且非阻塞的紧凑提醒面板；提前提醒出现后，用户未处理直到用眼截止时，系统必须自动开始休息。延后提醒到期时，系统必须显示相同的紧凑提醒并自动开始休息。

#### Scenario: 用户首次使用应用

- **当** 用户首次启动应用且尚未保存设置
- **那么** 系统必须使用唯一的专注提醒流程
- **并且** 设置页面不得显示提醒模式选择

#### Scenario: 提前提醒到期

- **当** 用眼计时剩余时间达到配置的提前提醒时间
- **那么** 系统必须显示透明、置顶且非阻塞的紧凑提醒面板
- **并且** 系统必须保持用眼计时状态
- **并且** 不得显示 Windows 通知、请求锁定 Windows 或在用户开始休息前关闭显示器

#### Scenario: 用户未处理直至用眼截止

- **当** 提前提醒已经显示且用户未作任何操作
- **并且** 用眼截止时间到达
- **那么** 系统必须自动开始休息
- **并且** 必须关闭当前提醒面板，并请求关闭显示器

### Requirement: 透明置顶紧凑提醒

提前提醒必须在当前活动显示器顶部显示透明、无边框、置顶且醒目的紧凑操作面板。面板不得抢夺焦点，不得覆盖整个显示器工作区，也不得阻止用户继续操作底层应用。面板可以使用平缓的呼吸、渐变或等效低刺激动效，但不得包含快速闪烁、高频颜色切换或伪装成 Windows 系统界面的内容。面板必须显示基于本轮绝对用眼截止时间实时计算的“距离休息还有”倒计时，并提供开始休息、延后提醒、暂停提醒、“知道了”和“跳过本次休息，继续当牛马”操作。

#### Scenario: 显示透明紧凑提醒

- **当** 系统进入提前提醒展示阶段或延后提醒到期
- **那么** 系统必须在当前活动显示器顶部显示由透明原生窗口承载且置顶的紧凑提醒面板
- **并且** 面板必须具有清晰可辨识的半透明底色、描边或阴影轮廓，不得因透明而难以察觉
- **并且** 必须显示持续更新的“距离休息还有”倒计时，以及可操作的开始休息、延后、暂停、“知道了”和“跳过本次休息，继续当牛马”按钮
- **并且** 不得创建覆盖整个显示器工作区的视觉窗口

#### Scenario: 提醒不阻止桌面输入

- **当** 透明紧凑提醒正在显示
- **那么** 窗口不得主动获取焦点
- **并且** 用户必须仍能操作面板之外的底层应用

#### Scenario: 重复提醒事件发生

- **当** 系统已经显示等待处理的紧凑提醒且再次收到相同状态更新
- **那么** 系统不得创建第二个提醒面板

#### Scenario: 透明提醒创建失败

- **当** 系统无法创建透明紧凑提醒面板
- **那么** 系统必须明确处理该错误或降级为普通置顶专注提醒窗口
- **并且** 不得丢失本次待处理提醒或可操作入口

### Requirement: 开始休息后关闭显示器

用户在提前提醒中选择开始休息，或用眼截止到达时用户仍未处理提前提醒时，系统必须开始休息倒计时、关闭当前透明提醒层和操作面板，并请求 Windows 关闭显示器。关闭显示器请求成功或失败都不得改变休息计时、完成休息或开始下一轮用眼计时。

#### Scenario: 用户开始休息

- **当** 用户在提前提醒中选择开始休息
- **那么** 系统必须开始休息倒计时并关闭当前提醒面板
- **并且** 系统必须请求 Windows 关闭显示器

#### Scenario: 关闭显示器请求失败

- **当** 用户开始休息后系统请求关闭显示器失败
- **那么** 系统必须继续保持休息计时
- **并且** 不得重新进入等待处理状态或提前开始下一轮用眼计时

### Requirement: 唤醒屏幕不完成休息

系统必须将显示器被鼠标、键盘或其他方式重新亮起视为外部显示器状态变化，而不是完成休息。休息只能在休息倒计时结束或用户明确选择提前结束休息时完成。

#### Scenario: 用户唤醒关闭的显示器

- **当** 系统已在休息期间请求关闭显示器且用户重新亮起屏幕
- **那么** 系统必须继续休息倒计时
- **并且** 不得仅因亮屏而完成、延后或暂停本次休息

#### Scenario: 休息结束

- **当** 休息倒计时结束或用户明确提前结束休息
- **那么** 系统必须开始新的用眼计时周期

## MODIFIED Requirements

### Requirement: 提前提醒倒计时必须实时更新

提前提醒面板必须显示距离本轮用眼截止的剩余时间。该倒计时必须使用状态机提供的绝对用眼截止时间减去当前时间计算，并至少每秒更新一次；不得因为进入等待处理状态而固定显示 0 秒。窗口重新显示、渲染暂停或系统睡眠恢复后，系统必须立即按当前时间重新计算。

#### Scenario: 提前提醒显示动态剩余时间

- **当** 提前提醒在原定用眼截止之前显示
- **那么** 面板必须显示大于 0 的实际剩余时间
- **并且** 可见数值必须至少每秒更新一次
- **并且** 不得在截止时间尚未到达时持续显示 0 秒

#### Scenario: 提醒窗口恢复后重新校准

- **当** 提醒窗口重新显示、渲染进程经历暂停或系统从睡眠恢复
- **那么** 系统必须根据当前时间和本轮绝对用眼截止时间重新计算剩余时间
- **并且** 不得通过对旧显示值累计减秒来恢复倒计时

### Requirement: “知道了”保持原关闭语义

提前提醒窗口必须提供明确的“知道了”按钮，替代原“关闭”显示文案。用户点击该按钮时，系统必须关闭当前提前提醒窗口及其操作面板，但不得将操作解释为开始休息、延后或暂停；用眼计时和原定截止时间必须保持不变。

#### Scenario: 用户确认知道了

- **当** 提前提醒正在显示且用户点击“知道了”
- **那么** 系统必须关闭当前提醒窗口
- **并且** 必须继续按照原定用眼截止时间计时
- **并且** 不得开始休息、暂停计时或修改下一次提醒时间

#### Scenario: 知道了之后到达原定截止时间

- **当** 用户已经点击“知道了”且原定用眼截止时间到达
- **那么** 系统必须按照既有规则进入休息流程

### Requirement: 用户可以跳过本次休息

提前提醒窗口必须提供“跳过本次休息，继续当牛马”按钮。用户点击后，系统必须关闭当前提醒，取消即将发生的本次休息，不请求关闭显示器，并从点击时刻开始一轮完整的用眼计时。该操作不得被解释为延后、暂停或开始休息。

#### Scenario: 用户跳过本次休息

- **当** 提前提醒正在显示且用户点击“跳过本次休息，继续当牛马”
- **那么** 系统必须关闭当前提醒窗口
- **并且** 不得进入休息计时或请求关闭显示器
- **并且** 必须从点击时刻开始一轮完整的用眼计时

#### Scenario: 跳过后旧截止时间到达

- **当** 用户已跳过本次休息且被跳过周期的原定截止时间随后到达
- **那么** 系统不得再次触发被跳过的休息或重新显示对应提醒
- **并且** 必须继续执行新一轮用眼计时

### Requirement: 提前提醒不得妨碍正常工作

提前提醒必须是最上层、透明、非阻塞的紧凑窗口：可以保持在其他窗口之上，但不得抢夺焦点、拦截视觉区域之外的鼠标或键盘输入、锁定 Windows、关闭显示器或阻止用户继续工作。提醒窗口不得覆盖整个桌面工作区；只有操作面板和按钮控件可以接收交互。

#### Scenario: 提前提醒以紧凑面板显示

- **当** 系统进入提前提醒展示阶段
- **那么** 系统必须只显示位于当前活动显示器顶部的紧凑提醒面板
- **并且** 不得创建覆盖整个显示器工作区的视觉窗口
- **并且** 面板必须显示实时剩余时间，以及开始休息、延后、暂停、“知道了”和“跳过本次休息，继续当牛马”操作

#### Scenario: 用户继续正常工作

- **当** 提前提醒正在显示
- **那么** 用户必须仍能操作底层应用
- **并且** 提醒不得主动改变焦点或阻止底层窗口接收输入

#### Scenario: 用户确认非阻塞提醒

- **当** 用户点击操作面板中的“知道了”
- **那么** 系统必须仅关闭提前提醒，不改变用眼计时计划
