## 目的

提供可恢复且可配置的本地用眼计时流程，使用户能够按照设定节奏开始休息、延后提醒或临时暂停提醒。

## ADDED Requirements

### Requirement: 可配置的休息方式

系统必须允许用户在“黑屏遮罩 + 休息倒计时”和“直接锁定 Windows”之间选择，并持久化该选择；默认值必须为黑屏遮罩。两种方式都必须由同一个绝对休息截止时间驱动。黑屏遮罩模式下，点击“提前结束休息”才可提前完成休息；锁定 Windows 模式下，Windows 解锁事件不得单独完成休息，系统必须依据休息截止时间决定继续休息或开始下一轮。

#### Scenario: 休息方式变更

- **当** 用户保存一种支持的休息方式
- **那么** 系统必须持久化该方式并在后续休息周期使用

#### Scenario: 休息结束

- **当** 休息截止时间到达，或黑屏遮罩模式下用户明确点击“提前结束休息”
- **那么** 系统必须结束本轮休息并开始下一轮完整的用眼计时

### Requirement: 可配置的护眼时间表

系统必须允许用户配置用眼间隔、休息时长、延后提醒时长和提前提醒时间。默认用眼间隔必须为 20 分钟，默认提前提醒时间必须为 30 秒；提前提醒时间支持范围必须为 0 至 300 秒，其中 0 表示不提前显示提醒。设置界面必须拒绝超出规定范围的值。

#### Scenario: 用户保存有效的时间表

- **当** 用户保存处于支持范围内的用眼间隔、休息时长、延后时长和提前提醒时间
- **那么** 系统必须使用新配置执行后续提醒周期

#### Scenario: 用户输入不支持的值

- **当** 用户尝试保存超出支持范围的值
- **那么** 系统必须显示校验错误，并保留之前保存的值

### Requirement: 提前提醒和默认开始休息

系统必须在用眼截止时间前达到用户配置的提前提醒时间时显示透明桌面动画提醒，同时保持用眼计时状态。提前提醒显示后，用户可以立即开始休息、延后或暂停；若用户在用眼截止时间到达前未作任何处理，系统必须自动开始休息，而不得进入无限等待用户操作的状态。

#### Scenario: 提前显示透明动画提醒

- **当** 用眼计时剩余时间首次小于或等于配置的提前提醒时间，且提前提醒时间大于 0
- **那么** 系统必须显示透明桌面动画提醒和可操作面板
- **并且** 系统必须继续保持用眼计时状态和原有用眼截止时间

#### Scenario: 不提前显示提醒

- **当** 用户将提前提醒时间设置为 0
- **那么** 系统不得在用眼截止时间之前显示透明桌面动画提醒

#### Scenario: 用户未处理提前提醒

- **当** 已显示提前提醒且用户未选择开始休息、延后或暂停
- **并且** 用眼截止时间到达
- **那么** 系统必须自动开始休息倒计时
- **并且** 不得进入等待用户操作的状态

#### Scenario: 用户在提前提醒中开始休息

- **当** 提前提醒正在显示且用户选择开始休息
- **那么** 系统必须立即开始休息倒计时

### Requirement: 提醒周期状态

系统必须跟踪以下状态：用眼计时、等待处理、已延后、已暂停和休息计时。系统不得同时运行多个有效的提醒倒计时或休息倒计时。

#### Scenario: 用眼间隔结束

- **当** 系统处于用眼计时状态且设定的用眼间隔结束
- **那么** 系统必须自动开始休息倒计时；若尚未显示提前提醒，则必须先显示提醒层并立即完成该状态转换

#### Scenario: 用户开始休息

- **当** 用户在提醒等待处理时选择开始休息
- **那么** 系统必须开始休息倒计时，并且在休息周期结束前不得安排下一次提醒

### Requirement: 延后、暂停和跳过本次休息控制

系统必须允许用户将等待处理的提醒延后指定时长，也必须允许用户选择一个支持的时长暂停提醒。系统还必须允许用户跳过本次休息；跳过后必须取消当前周期的待休息安排，并从操作时刻开始一轮完整的用眼计时。

#### Scenario: 用户延后提醒

- **当** 用户在等待处理的提醒中选择延后
- **那么** 系统必须在设定的延后时长结束后再次提醒

#### Scenario: 用户暂停提醒

- **当** 用户选择一个支持的暂停时长
- **那么** 系统必须在暂停结束前抑制提醒，暂停结束后恢复计时

#### Scenario: 用户跳过本次休息

- **当** 用户在等待处理的提醒中选择“我很强，这次先不休息”
- **那么** 系统必须取消本次休息并离开等待处理状态
- **并且** 必须以操作时刻加上完整用眼间隔作为新的用眼截止时间
- **并且** 不得开始休息倒计时、显示黑屏遮罩或请求锁定 Windows

#### Scenario: 跳过使旧调度失效

- **当** 系统已为当前周期安排到期事件且用户随后跳过本次休息
- **那么** 旧周期的提前提醒和到期事件必须被取消或判定为失效
- **并且** 旧事件不得改变新一轮用眼计时状态

### Requirement: 完成休息

系统必须在休息倒计时期间显示剩余休息时间，并在休息完成或黑屏遮罩模式下用户明确提前结束休息后开始新的用眼计时周期。

#### Scenario: 休息倒计时结束

- **当** 设定的休息时长倒计时归零
- **那么** 系统必须将本次休息标记为已完成，并开始新的用眼计时周期

#### Scenario: 用户提前结束休息

- **当** 用户处于黑屏遮罩模式并明确选择提前结束休息
- **那么** 系统必须结束当前休息状态，并开始新的用眼计时周期

### Requirement: 可见倒计时实时更新

主状态页面以及提前提醒面板在显示剩余时间时，必须根据当前状态的绝对截止时间持续更新可见倒计时。主状态页面适用于用眼计时、已延后、已暂停和休息计时状态；提前提醒面板必须继续使用本轮用眼计时的绝对截止时间，不得改用进入等待处理状态的时间或静态零值。倒计时在窗口保持打开时必须至少每秒更新一次，且不得仅显示首次读取状态时的静态快照。应用从后台恢复、系统睡眠恢复或窗口重新显示时，必须根据当前时间和绝对截止时间重新计算剩余时间，避免因渲染延迟产生累计漂移。

#### Scenario: 用眼计时实时更新

- **当** 应用处于用眼计时状态且主状态页面保持打开
- **那么** 页面显示的剩余时间必须至少每秒更新一次
- **并且** 剩余时间必须基于当前时间和本轮绝对截止时间计算

#### Scenario: 其他计时状态实时更新

- **当** 应用处于已延后、已暂停或休息计时状态且主状态页面保持打开
- **那么** 页面显示的对应剩余时间必须至少每秒更新一次

#### Scenario: 提前提醒倒计时实时更新

- **当** 提前提醒面板在本轮用眼截止之前保持显示
- **那么** 面板必须根据本轮绝对用眼截止时间至少每秒更新一次剩余时间
- **并且** 截止时间尚未到达时不得持续显示 0 秒

#### Scenario: 窗口恢复后校准倒计时

- **当** 主窗口从后台重新显示、应用从睡眠恢复或渲染进程经历较长时间暂停
- **那么** 页面必须使用当前时间和绝对截止时间重新计算剩余时间
- **并且** 不得通过累计递减导致明显漂移

### Requirement: 重启后重新开始用眼计时

系统必须在本地保存用户设置，但不得恢复应用上次运行中的用眼、延后、暂停、等待处理或休息计时状态。应用每次启动或重启后，必须按照已保存的设置创建一轮新的用眼计时。

#### Scenario: 应用在任意计时状态期间重启

- **当** 应用在用眼计时、等待处理、已延后、已暂停或休息计时期间重启
- **那么** 系统必须丢弃上次运行中的计时状态
- **并且** 必须按照已保存设置重新开始一轮完整的用眼计时
- **并且** 不得因为重启立即显示上次未处理的提醒或继续上次剩余时间

#### Scenario: 应用重启后保留用户设置

- **当** 用户在重启前已经保存用眼间隔、休息时长或延后时长
- **那么** 应用重启后必须继续使用这些设置创建新的用眼计时
