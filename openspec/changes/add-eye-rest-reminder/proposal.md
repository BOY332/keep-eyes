## 为什么需要这个变更

长时间连续面对屏幕容易让用户忽略休息时间。keep-eyes 需要提供一套简单、明确且不会妨碍正常工作的 Windows 护眼提醒流程：在用眼时间结束前先以位于每个已连接显示器顶部的透明、置顶、紧凑面板分别提醒用户主动处理；用户确认开始休息后，应用按用户选择进入覆盖所有屏幕的黑屏遮罩或直接锁定 Windows 模式。休息仍由独立倒计时管理；黑屏遮罩模式支持提前结束休息，锁定模式由用户自行解锁。

## 变更内容

- 新增 Windows 桌面护眼提醒应用的核心计时、休息和提醒流程。
- 支持保存用眼间隔、休息时长、延后提醒时长和提前提醒时间；提前提醒默认 30 秒，支持设置为 0～300 秒；休息方式支持“黑屏遮罩 + 休息倒计时”和“直接锁定 Windows”，默认使用黑屏遮罩。第一版不提供提醒方式选择或温和通知。
- 距离用眼时间截止达到提前提醒时间时，在每个已连接显示器的工作区顶部分别显示由透明原生窗口承载、具有清晰半透明底色与描边轮廓、置顶且不抢夺焦点的紧凑提醒面板；非按钮区域保持鼠标穿透。所有面板显示相同的、基于本轮绝对用眼截止时间计算的实时剩余时间，并提供开始休息、延后、暂停、“知道了”和“我很强，这次先不休息”；用户在任意一个屏幕上的操作都必须同步作用于本轮所有屏幕上的面板，且不得重复触发状态机事件。“知道了”仅隐藏面板且不改变原定截止时间；“我很强，这次先不休息”则取消本次休息、不进入任何休息呈现方式，并从点击时刻开始一轮完整的用眼计时。用户未处理时，用眼截止到达即自动开始休息。
- 用户选择开始休息，或在提前提醒后直到用眼截止仍未操作时，应用开始休息倒计时、关闭全部提前提醒面板，并按设置的休息方式覆盖所有屏幕显示黑屏遮罩，或直接锁定 Windows；两种方式都由同一个绝对休息截止时间驱动。
- 黑屏遮罩模式下，用户可在任意屏幕点击“提前结束休息”来结束本轮休息；锁定 Windows 模式下，用户必须先通过 PIN、密码或 Windows Hello 解锁，且解锁本身不等于休息完成。仅在休息倒计时结束，或黑屏遮罩模式下用户明确提前结束休息后，开始下一轮用眼计时。
- 提供系统托盘入口，用于查看状态、打开设置、立即开始休息、临时暂停提醒和退出应用。
- 在本地保存用户设置；应用每次启动或重启后都丢弃上次运行中的计时状态，并按当前设置重新开始一整轮用眼计时。
- 交付 Windows x64 的 `.exe` 安装程序，正式支持 Windows 10 x64 和 Windows 11 x64。安装程序必须允许用户选择安装路径，并提供 Windows 标准卸载入口；卸载时默认保留用户设置和本地数据，同时提供“删除全部设置和本地数据”的选项。

## 能力范围

### 新增能力

- `eye-rest-scheduling`：可配置的用眼计时、提前提醒、默认自动开始休息、延后、暂停、跳过本次休息、休息倒计时、全屏黑屏遮罩、提前结束休息、Windows 锁定模式、解锁后的休息判断和重启后重新开始计时行为。
- `eye-rest-alerting`：固定的多显示器透明置顶紧凑提醒、基于绝对截止时间实时显示提醒倒计时、“知道了”但保持原计划、跳过本次休息、所有屏幕黑屏遮罩和 Windows 锁定流程。
- `tray-and-settings`：系统托盘控制、时间设置页面、本地持久化以及 Windows 安装、卸载和本地数据清理行为。

### 修改能力

- 无。

## 影响范围

- 新增 Windows 桌面应用工程、主进程、渲染进程和受限预加载桥接层。
- 使用 Electron、React、TypeScript 和本地设置存储；核心计时状态机需要使用 Vitest 测试。
- 调用 Windows 工作站锁定能力，并提供不调用系统电源或锁定能力的黑屏遮罩模式；不调用显示器电源关闭、睡眠或休眠能力。
- 第一版仅面向 Windows，不包含登录、后端服务、云同步或医疗诊断功能。
- 最终用户交付物为 Windows x64 `.exe` 安装程序；不支持 Windows 32 位、Windows 7/8/8.1，Windows ARM64 不属于第一版承诺范围。
